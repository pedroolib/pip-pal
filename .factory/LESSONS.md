# Lessons
- Tell builders that `.factory/jobs/` is gitignored: give absolute job-folder paths, and have WP1 builders run `git checkout main -- src/shared/fixtures` after any prettier/lint --fix so fixtures stay untouched.
- Briefs for any code that sends text off-machine should state the PII rules up front (replacer functions not template strings, case-insensitive, trimmed names, one pass for all names); round 1 found all three the hard way.
- UX testers on the plain-browser build can't confirm persistence and hit state bugs (collapsed sections unmounting open editors). Ask UI builders to keep editor state mounted when a container collapses, and give testers a single-session script.
- Briefs for name/PII scrubbing must list the real-world name shapes up front (two-letter names, hyphens, curly apostrophes, @handles/underscores, NFKC/zero-width, names that are common words) and say tests must use multi-word names and a date-plus-time string; two review rounds were spent finding these one batch at a time.
- Builders cannot see the job folder: ask orchestrator-side for `wp-N.build.md` content in the final message and write it myself, so the approver can audit assumptions.
- Remove finished builder worktrees (inside .claude/worktrees) before running lint, or eslint reports their copies as errors.
- UI reviewers and UX testers share one Playwright browser: run them one after the other, not in parallel, or the tester sees the reviewer's test data (round 1 here reported "chips I didn't add"). Also start the dev server from the job branch (check `git branch --show-current` first) and never `pkill -f` a pattern that matches your own shell command.
- Scrubber rework briefs must forbid deleting separators: when cleaning roles or tokens, replace a character with a space, never with '', because joining words hides names from the matcher (round 2 here: "lead@Sam" → "[leadSam]"). Ask builders to rerun every earlier round's failing inputs plus one "separator next to a name" case.
- An invisible hit area (`after:-inset-*`) needs `overflow-visible` on every ancestor up to the clickable size; shadcn Badge has `overflow-hidden`. Tell the UI reviewer to test hit areas with elementFromPoint at the edge, not by measuring the pseudo-element.
- When a fix changes a core algorithm (e.g. the scrubber matcher), have the builder keep the old implementation as a test-only reference and assert byte-identical output on every existing input plus a generated corpus; it let 3 security rounds verify equivalence instead of re-hunting leaks. Add the new WP to tickets.md before spawning, so the approver sees declared scope.
- Removing a builder's worktree after merging makes SendMessage resume fail ("worktree no longer exists"). For fix rounds, spawn fresh builders whose first step is `git checkout -B <wp>-rN factory/<id>` in their worktree, and give them the review paths; remove worktrees only right before running lint.
- UX testers re-raise settled product choices (wording, what to hide) every round, and the ux-tester does not write its report file. Between rounds, settle those points with the user in one AskUserQuestion, save the tester's message as `round-<n>/ux.md` yourself, and pass the settled points to reviewers as "not defects".
- When a fix restores window size or position from the renderer (`screenX/screenY` → `setOverlayBounds`), brief the builder to run it only on the transition that needs it, never on every render of a view: on first launch and on Hyprland those values can be stale or 0 (round 2 here).
