# Lessons
- Tell builders that `.factory/jobs/` is gitignored: give absolute job-folder paths, and have WP1 builders run `git checkout main -- src/shared/fixtures` after any prettier/lint --fix so fixtures stay untouched.
- Briefs for any code that sends text off-machine should state the PII rules up front (replacer functions not template strings, case-insensitive, trimmed names, one pass for all names); round 1 found all three the hard way.
- UX testers on the plain-browser build can't confirm persistence and hit state bugs (collapsed sections unmounting open editors). Ask UI builders to keep editor state mounted when a container collapses, and give testers a single-session script.
- Briefs for name/PII scrubbing must list the real-world name shapes up front (two-letter names, hyphens, curly apostrophes, @handles/underscores, NFKC/zero-width, names that are common words) and say tests must use multi-word names and a date-plus-time string; two review rounds were spent finding these one batch at a time.
- Builders cannot see the job folder: ask orchestrator-side for `wp-N.build.md` content in the final message and write it myself, so the approver can audit assumptions.
- Remove finished builder worktrees (inside .claude/worktrees) before running lint, or eslint reports their copies as errors.
- UI reviewers and UX testers share one Playwright browser: run them one after the other, not in parallel, or the tester sees the reviewer's test data (round 1 here reported "chips I didn't add"). Also start the dev server from the job branch (check `git branch --show-current` first) and never `pkill -f` a pattern that matches your own shell command.
- Scrubber rework briefs must forbid deleting separators: when cleaning roles or tokens, replace a character with a space, never with '', because joining words hides names from the matcher (round 2 here: "lead@Sam" → "[leadSam]"). Ask builders to rerun every earlier round's failing inputs plus one "separator next to a name" case.
- An invisible hit area (`after:-inset-*`) needs `overflow-visible` on every ancestor up to the clickable size; shadcn Badge has `overflow-hidden`. Tell the UI reviewer to test hit areas with elementFromPoint at the edge, not by measuring the pseudo-element.
- When a fix changes a core algorithm (e.g. the scrubber matcher), have the builder keep the old implementation as a test-only reference and assert byte-identical output on every existing input plus a generated corpus; it let 3 security rounds verify equivalence instead of re-hunting leaks. Add the new WP to tickets.md before spawning, so the approver sees declared scope.
- Removing a builder's worktree after merging makes SendMessage resume fail ("worktree no longer exists"). For fix rounds, spawn fresh builders whose first step is `git checkout -B <wp>-rN factory/<id>` in their worktree, and give them the review paths; remove worktrees only right before running lint.
- UX testers re-raise settled product choices (wording, what to hide) every round, and the ux-tester does not write its report file. Between rounds, settle those points with the user in one AskUserQuestion, save the tester's message as `round-<n>/ux.md` yourself, and pass the settled points to reviewers as "not defects".
- When a fix restores window size or position from the renderer (`screenX/screenY` → `setOverlayBounds`), brief the builder to run it only on the transition that needs it, never on every render of a view: on first launch and on Hyprland those values can be stale or 0 (round 2 here).
- shadcn `RadioGroupItem` renders no children: brief builders to wrap each item in a `Label` with the visible text (round 1 here shipped four empty recipient pills). Likewise, Tailwind v4 `outline-none` + `focus-visible:outline-3` draws nothing without `focus-visible:outline-solid`; put both in UI briefs.
- The auto-mode classifier blocks a bulk `git worktree remove --force` loop: merge first, check each worktree's `git status` is clean, then remove them one at a time without `--force`.
- Builders can't do a visual check while the orchestrator's dev server holds port 3000. For fix rounds, either stop the server before spawning the builder, or tell the builder to use a second port and say so in the brief.
- On this Windows machine the Playwright MCP fails with "spawn UNKNOWN", so the reviewer-ui and ux-tester can't see anything. Check that it launches before stage 6. If it doesn't, the orchestrator does the UI pass in the built-in browser and writes `round-<n>/ui.md` itself.
- `forRecipient` empties `people`, so `buildProfileContext(forRecipient(...))` sends names unswapped. Any brief for code that sends recipient-filtered data to Claude must say to scrub with the full profile's people and aliases.
- Mock API methods that change state (`refreshLearned` here) must write to the mock's own state, or the plain-browser review misses the next screen. Put "mock writes persist across calls" in WP1 contract briefs.
- Radix `RadioGroupItem` is a `<button role="radio">`, so a keydown guard on `HTMLButtonElement` swallows Enter while a radio has focus. Tell UI builders to check the role, and test Enter with a radio focused.
- Fix rounds that split findings across builders can drop some (voice capture round 1 left code 5 and 8 unfixed, because each report only listed what it did). Have the orchestrator tick every numbered finding as fixed or deferred before merging.
- Check docs against the code before calling something done: DECISIONS said the cards call `api.logEvent`, but no renderer code did. Ask reviewers to grep for the caller when a doc says something is wired.
- State the threat model in the spec before round 1: Pip's is accidental leaks in good-faith use, not crafted input. Here it came mid-job, after a round spent on nested tags and hostile strings, and it left criterion 7 ("nothing the old code scrubbed may leak") contradicting the accepted crafted rows. If the model changes mid-job, reword the criteria the same moment.
- A byte-identity reference only proves what it can see. Here it agreed with the old leak at contact edges and had no tag strip, so a real regression passed every gate until security fuzzed against main. Scrubber differentials compare with main's whole path (scrub plus strip), and check the corpus really contains the new character: the old ones held no Cf at all.
- In a worktree session a hook blocks writes to the main checkout, so create the job folder in the worktree before spawning anything and put that path in the brief; `/factory:status` from main will not list it. Give builders job-unique branch names: `wp1-r1` and `fix-r1` are held by other jobs' worktrees.
- `preview_start` serves the main checkout whatever the session's folder is, and `--rendererOnly` still launches Electron. To review a job branch, stop it and serve the job worktree with a temporary uncommitted vite config on port 3000, and check the served path with `curl /src/Overlay.tsx` before trusting a screenshot.
- Any text cleanup placed in front of the scrubber must be tested against the scrubber's whole catch list (emails, links, handles, joined and suffixed names), asserting nothing it caught is lost. Round 2 here found a guard from the fix round broke addresses. Don't add new scrubber-adjacent logic in the last fix round; send it to its own job.
- A UI section hidden when empty can't be reviewed in a plain browser unless the mock seeds it. Put "seed anything hidden when empty" in the contract WP brief.
